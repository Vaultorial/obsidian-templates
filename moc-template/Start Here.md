# Start Here

Welcome. This vault demonstrates Maps of Content (MOCs) — the middle layer between "one giant index" and "no structure at all". It ships with one home MOC, three topic MOCs and fifteen real notes underneath them, so the graph view already shows you the shape the method produces.

## The three levels

1. **[[Home MOC]]** — the single front door. Links only to MOCs, never directly to notes.
2. **Topic MOCs** — [[Productivity MOC]], [[Learning MOC]], [[Writing MOC]]. Each gathers and *arranges* the notes of one topic, with a line of context per link.
3. **Notes** — one idea each, living flat in the `Notes` folder. Folders stay dumb; the MOCs carry the structure.

Every note carries an `Up:` line pointing to its MOC, so you can always climb back out. Cross-links between notes are encouraged — the MOC tree gives orientation, the cross-links give the graph its texture.

## First steps

1. Open [[Home MOC]], pick a topic, and follow it down to a note. Notice the path: home → MOC → note → sibling notes.
2. Open the graph view. Three clusters around three hubs — that is the method, visible.
3. Add a note of your own to whichever topic is closest, give it an `Up:` link, and add it to that MOC with a phrase of context.
4. When some new topic accumulates seven to ten loose notes, create its MOC from [[MOC Template]] and add it to [[Home MOC]].

## Plugins

None needed. The core **Templates** plugin is preconfigured to the `Templates` folder for creating new MOCs.

> [!tip] MOCs are written, not generated
> The value of a MOC is the curation: which notes made the cut, in what order, with what one-line commentary. A list of every note tagged with a topic is a search result, not a map.
